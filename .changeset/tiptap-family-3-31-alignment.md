Move the whole Tiptap editor family onto one 3.31.3 release line so `@tiptap/core` runs against the `@tiptap/pm` it declares.

Fizzy #2451. `@tiptap/core` declares an **exact** peer on `@tiptap/pm` at its own version, and advisory bumps had moved core to 3.31.3 while `@tiptap/pm`, `@tiptap/react` and `@tiptap/starter-kit` stayed on the 3.14.0 line the editor was integrated against. The extensions had drifted apart rather than staying put together — most on 3.14.0, but `extension-unique-id` on 3.22.3, `extension-mention` resolving to 3.22.5, `extension-typography` and `suggestion` on 3.10.7, `html` on 3.22.5. pnpm's non-strict peer mode accepted the whole arrangement (`pnpm install` printed "Issues with peer dependencies found"), so this was latent rather than a live defect — but core 3.31.3's code was running against a ProseMirror re-export bundle 17 minors behind it.

The 3.31.3 packages wire themselves together with exact intra-family edges wherever they declare one — `@tiptap/core` and `@tiptap/react` take `@tiptap/core` and `@tiptap/pm` as exact peers, `extension-table` likewise, `extension-highlight` and `extension-typography` pin only core, `extension-color` pins only `extension-text-style`, and `starter-kit` pins its extensions as exact *dependencies* rather than peers. A mixed-version island is therefore unsupported, so the family moves as a unit. Bumping `@tiptap/pm` alone is worse than it looks in any case: 3.31.3 drops the `collab`, `markdown`, `menu`, `schema-basic` and `trailing-node` subpath re-exports, which `@tiptap/extension-collaboration@3.14.0` imports. `@tiptap/y-tiptap` goes to 3.0.9 because the 3.31.3 collaboration extensions require `^3.0.7`.

The four subpaths this repo actually imports — `@tiptap/pm/model`, `/state`, `/view`, `/transform` — all survive the removal, and no source file imports a dropped one.

Three ProseMirror packages also get single-copy override floors. `@tiptap/pm` 3.31.3 pins `prosemirror-model` ^1.25.11, `-view` ^1.42.3 and `-transform` ^1.12.0, while the other ProseMirror packages (state, commands, tables, schema-list, …) declare looser `^` ranges that pnpm satisfied with the copies already in the lockfile. That left two `prosemirror-model` copies on the tree and two structurally distinct `Node`/`NodeSpec` types, so passing a node from `@tiptap/pm/model` into a ProseMirror plugin stopped type-checking (TS2345 in the sidekick instruction-suggestion extension, three call sites). The floors collapse each back to one copy, which is also what keeps ProseMirror's runtime identity common across Tiptap, tables, state and Yjs. A plain `pnpm install` reproduces the split without them, so this is a property of the bump and not of the lockfile merge.

The lockfile is hand-merged per the repo convention rather than regenerated: master's text everywhere, the fresh resolve's text only for the `@tiptap/*` / `prosemirror-*` / `@remirror/*` / `linkifyjs` subtree, which is self-contained (no key outside it carries a subtree peer suffix). That keeps the diff to a third of the raw regen's and drops the usual re-resolution churn — a `sass@1.51.0` peer suffix appearing on four `next@16.3.4` consumers, a `@floating-ui` 1.7.x dedupe, and `uuid`/`@types/markdown-it` movement in unrelated snapshots. `linkifyjs` moves 4.3.2 → 4.3.3 as a genuine new requirement of `@tiptap/extension-link@3.31.3`; its old entry, and `crelt` (reachable only through the dropped `prosemirror-menu`), are pruned rather than left as orphans.
