Coding Instructions repository sync now lets you exclude folders under the synced folder from its tree, and shows which folders and files the sync will skip and why.

Fizzy #2726. Each folder under the chosen one gets an "Exclude" toggle that stages `<folder>/**` in the project's own ignore rules (seeded with the defaults when the project has none). Nothing is written until "Save and sync": the dialog re-reads the saved rules, applies the staged edits to them, and sends the result with `configure`, which writes the rules and the sync configuration in one transaction — so a refused branch or a failed configure saves neither. `configure` requires INSTRUCTION_UPDATE as well when it carries rules, and audits a change to them as `project.instructions.settings_updated`. Staged edits are dropped when the folder, branch or repository changes. Files are judged by the sync's own `resolveIgnoreGlobs` and `buildIgnoreMatcher` on their own path, as `planSnapshotFiles` judges them, and a symbolic link always shows as skipped, since the sync reads regular files only (`listRepositoryTree` now marks one `regular: false`: GitHub blob mode `120000`, Azure DevOps `isSymLink`); a folder reads as skipped only when the rule skips everything in it. A new `projects.instructions.repositorySync.readIgnoreFile`, gated exactly like `listTree`, reads the chosen folder's `.fabricignore` through `@repo/connectors`' new capped `readRepositoryFile` (GitHub and Azure DevOps, at most the sync's 64 KiB, and only a regular file — a folder, submodule or symbolic link there is absent, as the sync treats it); when that file has rules it replaces the project's, so the toggles are disabled and the tree shows its exclusions. `MAX_FABRICIGNORE_BYTES` now lives in `@repo/instructions`.
