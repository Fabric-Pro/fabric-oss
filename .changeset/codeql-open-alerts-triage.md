Frame PDF export sanitises a frame's joined HTML blocks until nothing more can be removed and no longer lets markup split across two blocks, reference-encoded script URLs, non-image `data:` URLs or attributes written without a preceding space through, and several parsers of uploaded or synced text now run in linear time on hostile input.

The frame export sanitiser runs once over all of a frame's blocks as they are joined into the page, so a tag, handler or script URL split across two blocks (`<img src=x` then `onerror=…>`) is caught. It repeats until a removal can no longer join the text around it into a new handler, tag or script URL, and drops the blocks if they are still changing after ten passes. It reads a URL's scheme the way a browser does (`javascript&colon;`, `&#106;avascript:` and friends are caught), removes every `data:` URL except raster images, catches `<img src="x"onerror=…>` and `<img/onerror=…>`, and removes a dangerous tag left unterminated at the end of the HTML. It does not sanitise CSS: `<style>` content, CSS escapes such as `\75rl(`, `image-set()` and `@import` pass through, and its removal of an inline `style` that literally contains `url(`, `expression(` or `javascript:` (now also unquoted or reference-encoded) is best effort. What CSS asks to fetch is stopped by the render context, which runs with JavaScript off, offline, and every request aborted.

Linear-time rewrites, each returning what the old pattern returned on well-formed input: the frame sanitiser's attribute and tag scans; scope-intake's row, dependency and area-header parsing of uploaded documents; the coding-run spike prompt's untrusted-data marker stripping; merged-PR and code-search repository URL normalisation; story identifier ordering; coding-instructions frontmatter key parsing; MCP tool-name repair; the orchestrator's word split of tool-call arguments for risk assessment; and PM sync's change-detection normalisation and GitLab attachment-block handling, whose digests are unchanged for every input. The one visible difference is that a scope-document dependency row containing a lone carriage return (CR), U+2028 or U+2029 now parses instead of being skipped.

The MCP `fabric_add_instruction_lesson` tool now also refuses a lesson title containing a C1 control character or a Unicode line or paragraph separator (U+2028, U+2029), as it already did for other control characters.

SECURITY.md's Code Scanning triage policy gains rules for `js/incomplete-url-scheme-check`, `js/bad-code-sanitization` and `js/identity-replacement`, and states that multi-character sanitisation at an HTML sink repeats to a fixed point over the final string the sink receives, with CSS contained by the renderer rather than the filter.
