Bump the pinned pnpm from 10.14.0 to 10.34.5, the current 10.x release.

The pin was thirteen months old (10.14.0 shipped 2025-07-31). Moving to the
last 10.x brings a year of installer fixes and makes the opt-in
`minimumReleaseAge` / `minimumReleaseAgeExclude` supply-chain settings
(introduced in 10.16 / 10.17) available without a major-version migration.
pnpm 11 is deliberately not taken here: it stops reading `package.json#pnpm`
(where this repo keeps its overrides and build-script lists), restricts
`.npmrc` to auth/registry keys, and replaces `onlyBuiltDependencies` /
`ignoredBuiltDependencies` with `allowBuilds`, so it needs its own change.

Lockfile is untouched: `pnpm@10.34.5 install --lockfile-only --frozen-lockfile`
exits 0 with no diff (lockfileVersion 9.0 is shared across the 10.x line).
`packages/mcp-stdio-wrapper/Dockerfile` already floated on `pnpm@10`, which
resolves to 10.34.5, so one image has been building with this version.

Every hard-coded pin moves together: `package.json#packageManager`, the web,
temporal and database-migrate Dockerfiles, the twelve LangChain agent
Dockerfiles, `fabric/standards/global/tech-stack.md`, and the requirements line
in `CLAUDE.md` / `AGENTS.md` (whose Node floor is also corrected from 22.11 to
the 22.19 that `package.json#engines` actually declares). CI's
`pnpm/action-setup` steps and Vercel read `packageManager`, so they follow.

The temporal, database-migrate and mcp-stdio-wrapper images also move their
service-account home from `/home/<user>` to `/var/lib/<user>`. The relay's
publication scan rejects any path under `/home` as a developer home directory,
and these three Dockerfiles had carried theirs since the seed commit unnoticed
because nothing had touched them since; the first PR to change two of them was
refused head-bound. `HOME` (tsx cache, git config, the wrapper's npm cache and
Playwright's browser cache) follows the new directory, which `adduser --home` /
`useradd -m -d` create and own exactly as before.
