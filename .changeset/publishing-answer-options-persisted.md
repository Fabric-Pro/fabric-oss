Show the answers a publishing question is generated with — including Approved and Not approved for an asset that needs approval — as choices to pick, instead of only a free-text box. An open question already on a topic gains its choices the next time the topic's planning analysis is regenerated.

The Planning & Analysis activity resolves each question's pickable answer options — the two-choice Approved/Not-approved pair for an asset needing approval, or the model's own suggested answers — but never handed them to the database layer that reconciles questions into `publishing_topic_decision_entry` rows. Every stored row therefore carried no options, and the Summary & Questions panel had nothing to render option buttons from, regardless of how many options the analysis actually computed.

`ReconcilableQuestion.answerOptions` is now a required field rather than an optional one: the reconciliation writer stores `answerOptions ?? DbNull` on both create and on every refresh, so an omitted field was not merely absent from a new row — on a regeneration it silently erased any options already stored for an existing one. Making the field required means the one production caller can no longer compile while dropping it.

Two panel defects were dormant until rows actually started carrying options. Opening an option in the editor and submitting it unchanged used to be recorded as an edited answer rather than an accepted suggestion, because the check compared the typed text against a single recommended answer that an option-only question never has. And a viewer who cannot answer used to see an empty "Suggested:" line and nothing else, because the options were never checked before falling back to that line. Both are fixed: submitting an option unchanged is now recorded as an accepted suggestion, and a read-only viewer now sees the options themselves. Choices that arrive while a question is already on screen now replace an editor nobody opened, and asking someone about a question with nothing to accept no longer leaves an empty suggestion behind.

Tests: a new activity-level case pins that a question's stored options equal the same question's options in the analysis's own record, guarded against passing vacuously when the fixture carries no options at all; the existing reconciliation-row projection test now covers the field too; a deliberate removal of the fix was confirmed to fail both before being reverted; new panel-level cases cover an option submitted unchanged, a read-only viewer's view of both the options and the single-recommendation fallback rendered as a list, options arriving after the question is already on screen (including a draft in progress surviving them), and asking someone about a question with nothing to accept; and two database-level cases assert what the reconciler actually writes for a question's options on both the create and the refresh path.
