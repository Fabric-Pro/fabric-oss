Coding Instructions and Living Memory repository syncs are faster on hostile input, hide their data from organization members with no project tie, and report failed syncs with the exact limit they hit.

Hardening from a review of both syncs, shipped together.

Coding Instructions: the secret scan and the glob matcher now run in linear time (single-pass matchers replace the credential-assignment and JWT regular expressions and the glob translation; equivalence tests pin the old verdicts). The core instruction procedures and the v1 project resolution answer an organization member with no project tie as a missing project. A single snapshot read applies the proposal visibility the list applies. The auto-publish audit row is written inside the publish transaction, a rejection cleans up its staged bytes even after the uploader lost access, and prune and delete sweep a snapshot's staging and promoted prefixes. A `.fabricignore` that is not valid UTF-8 is rejected as `ignore_encoding` rather than `ignore_mismatch`. A kept set over the file or total size limit is reported as that limit rather than as a repository size. Activity heartbeats carry counters, never paths, and `@mentions` in a proposal's pull request title and description no longer notify anyone. The tab shows a skeleton while loading and an error with Retry when the published version or version list cannot be read; the file tree search gets a focus ring, a polite no-matches message and collapsible folders; the sync status live region stays mounted; sync action failures use translated messages and the configure dialog ignores close requests while saving.

Living Memory: a failed sync is shown beside the applied line with the limit and measured value it hit (new nullable `limitDetail` column and a `reapCheckedAt` column on `project_context_repository_sync_run`, both additive). A failed read of the sync state shows an error with Retry instead of nothing. Stranded receipts are completed hourly with a `repository_sync_completed` audit row, as are the receipts that `begin` reconciles. The sync's index step joins an embedding pass for a row that is still open instead of starting another. A `.contextignore` rule with more than two `**` groups, which the matcher cannot evaluate in bounded time, fails the run with a message naming its line instead of stalling the worker, and is never dropped or evaluated (new `IGNORE_RULE_REJECTED` error value, additive). The reaper's claim has a partial index on open receipts.

Internal: the reaper runs as a third `patched()` step of `projectInstructionReaperWorkflow` (`instruction-reaper-stranded-context-sync-receipts`); no other existing workflow's control flow changed. `@repo/instructions` exports `compileGlob`, `foldRegExpCase`, `decodeFabricIgnore` and `snapshotOwnedPrefixes`; `globToRegExp` is gone.
