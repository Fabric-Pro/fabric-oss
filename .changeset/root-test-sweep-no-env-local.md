Stop the root `pnpm test` sweep from automatically sourcing `.env.local`, so local credentials no longer flow into unit tests (Fizzy #2412)

The root `test` script was `dotenv -c -- turbo test`, so every workspace's `vitest run` under the root sweep inherited whatever `turbo.json` permits into the task environment from the developer's `.env.local`: database URLs, but also Upstash, Anthropic, Resend, Stripe and Qdrant credentials (turbo runs in strict env mode, so only variables declared in `globalEnv` and the pass-through lists cross into a task). CI runs `turbo run test` bare and the per-package `pnpm --filter <pkg> test` scripts are bare `vitest run`, so the root sweep was the only path on which an environment-gated client resolved to a real instance. Fizzy #2410 was the concrete failure: `brute-force.test.ts` left `../redis-client` unmocked and incremented a real `bf:ip-locks` counter on every sweep until the IP black-hole branch flipped three assertions, while the isolated run and CI stayed green.

The script is now `dotenv -e .env.test.local -- turbo test`: it sources only `.env.test.local`, a gitignored file intended (not enforced) to hold nothing but `DATABASE_URL` and `DIRECT_URL` (`.env.test.local.example` is the template), and dotenv-cli loads nothing when the file is absent, so CI and a fresh clone behave exactly as before. Variables exported by the shell still cross into tasks as they always did: turbo forwards every name in its `globalEnv` list, and this change narrows what the script sources, not what the shell provides. An audit of the default include set found no suite that fails without `.env.local`: every database-backed test gates on `hasReachableDatabaseUrl()` or an equivalent that treats an absent `DATABASE_URL` and CI's placeholder identically, `@repo/database` and `@repo/temporal` supply the placeholder in their vitest configs, and every Redis, AI-provider, Qdrant, Temporal and Resend client reached by a test is mocked with `vi.mock` plus `vi.resetModules()`. The roughly sixty database-gated suites that used to run against the local Postgres because `.env.local` happened to carry the URL keep running for anyone who creates `.env.test.local`; without it they self-skip, exactly as they do in the unit-tests workflow. The packages' `test:db`, `test:rls`, `test:integration` and `test:rag` scripts still load `.env.local` themselves, and `db-integration.yml` still runs the database suites against a real Postgres in CI. One remaining asymmetry with CI: the unit-tests workflow also sets a placeholder `DATABASE_URL`/`DIRECT_URL` at job level; a bare local sweep leaves them unset, which every reachability gate and both vitest-config defaults treat the same way.

A per-package `setupFiles` guard that unsets credential keys was considered and rejected for now: it would need wiring into seventeen vitest configs and every future package, and it protects against a shell that exports credentials rather than against the script that was actually injecting them.
